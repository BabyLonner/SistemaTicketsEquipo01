Documentación de la API

Todas las rutas responden JSON y piden un token JWT, salvo /api/login.

1. Obtener el token

POST {{ request.host_url }}api/login
Content-Type: application/json

{"correo": "victor.melgarejo@grupomm.com.pe", "password": "Clave123"}

La respuesta trae data.token. En Postman ponlo en Authorization → Bearer Token o como header:

Authorization: Bearer eyJhbGciOiJIUzI1NiIs...

POST /api/logout invalida el token (se guarda en tokens_revocados).

2. Rutas REST

  • GET /api/yo — usuario del token
  • GET /api/tickets — listado por urgencia (filtros: q, estado, prioridad, tecnico, urgentes=1)
  • POST /api/tickets — crear (form-data: asunto, descripcion, categoria_id, prioridad, fotos×3)
  • GET /api/tickets/<id> — detalle con evidencias e historial
  • POST /api/tickets/<id>/asignar — {"tecnico_id": 3, "comentario": "..."}
  • POST /api/tickets/<id>/estado — {"estado": "En proceso", "comentario": "..."}
  • POST /api/tickets/<id>/comentarios — {"comentario": "..."}
  • GET /api/tickets/<id>/historial
  • DELETE /api/tickets/<id>
  • GET /api/notificaciones, /api/notificaciones/contador
  • POST /api/notificaciones/<id>/leer, /api/notificaciones/leer-todas
  • GET /api/dashboard — resumen (desde, hasta, area, responsable)
  • GET /api/usuarios (administrador) · /api/empresas (superusuario)

3. Rutas de la colección de Postman

Siguen con las mismas URL (/api_insertar_*, /api_obtener_*) y responden {status, data, message}. Ahora también piden el token y respetan la empresa del usuario.

Códigos HTTP

  • 200/201 correcto · 400 datos inválidos · 401 sin token o vencido · 403 el rol no tiene permiso · 404 no existe o es de otra empresa · 413 archivo muy grande
